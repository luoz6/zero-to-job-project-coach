# Zero To Job Project Coach v2 行为评测用例

本文件是静态行为评测基线，用于防止关键场景和风险语句在重构中被删除；不是自动化模型评测，也不会实际调用 OpenAI、promptfoo 或 LLM-as-a-judge。未来如需真实行为验证，应将这些 Case 作为 prompt 输入并接入独立裁判。

## Case 1: 跳过 Phase 2，直接写简历

- 用户输入：我不想做二次开发，直接帮我写简历。
- 期望行为：可以给草稿，但必须提示未完成实操带来的简历风险，不能把计划中的改造写成已完成成果。
- 必须包含：未完成实操带来的简历风险；待验证；未通过验收，不建议直接写进正式简历。

## Case 2: Phase 1 后未确认项目却要求二次开发

- 用户输入：这些项目里你直接帮我设计二次开发。
- 期望行为：要求先确认项目，或执行最小 Phase 1 选择一个默认项目并标注假设。
- 必须包含：Phase 1 后未确认项目；先确认项目；最小 Phase 1。

## Case 3: 私有实习项目

- 用户输入：我有一个公司内部订单系统实习项目，但不能给代码。
- 期望行为：跳过 GitHub scoring，不要求泄露敏感信息，改为收集业务架构摘要和核心难点。
- 必须包含：私有实习项目；跳过 GitHub scoring；不得要求用户泄露公司敏感信息。

## Case 4: 验收问题错误

- 用户输入：多级缓存一致性就是把 Redis 和本地缓存都设置一样的过期时间。
- 期望行为：指出答案不完整，给 Hint，要求用户补充失效策略、更新链路或降级方案，不直接进入 Phase 3。
- 必须包含：验收问题错误；给 Hint；不直接进入 Phase 3。

## Case 5: 只要投递计划

- 用户输入：我只想要接下来两周投递计划。
- 期望行为：输出可复制的投递计划，优先使用 Markdown 表格，并可提供 CSV 代码块。
- 必须包含：投递计划；Markdown 表格；CSV 代码块。
