# 岗位路径与里程碑验收库

## 使用规则

本文件用于 Phase 1 的岗位拆解、Phase 2 的验收标准校准，以及 Phase 3 的项目表达防守。不要把岗位模板机械当作完整课程表，必须结合用户水平、时间预算和目标 JD 裁剪。

每个岗位都按五个字段使用：底层基线、进阶能力、推荐项目类型、最低简历项目标准、里程碑验收问题。

评分时结合 github_scoring_matrix.md，验收时结合本文件的里程碑问题。

## Java 后端

- 底层基线：Spring Boot 请求生命周期、MyBatis 映射与事务边界、AOP 切面、Redis 基础缓存、消息队列基本生产消费模型、数据库索引与慢查询分析。
- 进阶能力：多级缓存、异步解耦、幂等处理、限流熔断、服务治理、部署工程化、日志与监控。
- 推荐项目类型：电商、票务、权限系统、低代码后台、内容社区、订单履约系统。
- 最低简历项目标准：能跑通核心业务闭环，能说明接口设计、数据模型、缓存策略、异常处理和至少一个可验证的二次开发点。
- 里程碑验收问题：为什么这里使用 AOP 而不是普通拦截逻辑？Redis 缓存如何处理穿透、击穿和雪崩？消息队列消费失败如何重试和保证幂等？

## 前端

- 底层基线：组件拆分、状态管理、路由、表单校验、接口联调、权限路由、构建与部署。
- 进阶能力：性能优化、虚拟列表、可视化图表、低代码配置、端到端测试、错误监控、组件库封装。
- 推荐项目类型：SaaS 控制台、数据看板、低代码页面搭建器、协同编辑、移动端 H5。
- 最低简历项目标准：能解释页面架构、状态流转、接口缓存、权限控制、性能指标和一个复杂组件的实现细节。
- 里程碑验收问题：首屏慢如何定位？状态为什么放在全局而不是局部？复杂表单如何保证可维护性？

## AI 应用开发

- 底层基线：RAG 基本链路、LangChain 或同类编排框架、向量数据库、Embedding、Prompt 模板、最小可运行 AI 应用。
- 进阶能力：检索召回优化、重排、流式响应、工具调用、对话记忆、评测集、成本与延迟控制。
- 推荐项目类型：知识库问答、客服助手、代码助手、合同审查、简历匹配、企业文档检索。
- 最低简历项目标准：能跑通数据导入、切分、向量化、检索、生成和评测闭环，并能说明准确率、延迟或成本的预期目标。
- 进阶验收点：解释 TextSplitter 对 chunk 大小、Embedding 表达、召回准确率和上下文污染的影响。
- 里程碑验收问题：为什么选择这个向量数据库？RAG 幻觉如何评估和缓解？召回结果不相关时先查哪几个环节？

## 数据分析

- 底层基线：SQL、指标口径、数据清洗、可视化、A/B 分析、业务归因。
- 进阶能力：自动化报表、数据质量校验、用户分群、漏斗分析、预测模型、BI 权限治理。
- 推荐项目类型：电商经营分析、用户增长分析、广告投放分析、风控看板、物流履约分析。
- 最低简历项目标准：能说明指标定义、数据来源、清洗逻辑、分析结论、业务建议和可复现报表。
- 里程碑验收问题：GMV、订单数和支付用户数的口径如何定义？异常值如何处理？结论如何转化为业务动作？

## DevOps

- 底层基线：Linux、Docker、CI/CD、Nginx、日志采集、基础监控、环境变量和密钥管理。
- 进阶能力：Kubernetes、灰度发布、自动回滚、容量规划、可观测性、成本治理、故障演练。
- 推荐项目类型：一键部署平台、CI/CD 模板、监控告警系统、日志检索平台、服务发布系统。
- 最低简历项目标准：能解释部署链路、回滚策略、监控指标、告警规则和一次故障排查流程。
- 里程碑验收问题：发布失败如何回滚？如何区分应用异常和基础设施异常？容器健康检查如何设计？

## Go 后端

- 底层基线：gin/hertz 路由与中间件、GORM 数据访问、go-zero 或同类工程化脚手架、Redis 基础缓存、消息队列基本消费模型、配置管理与日志。
- 进阶能力：微服务治理、限流熔断、并发控制、异步任务、链路追踪、部署工程化与性能排查。
- 推荐项目类型：订单系统、支付链路、内容服务、网关、任务调度平台、轻量微服务后台。
- 最低简历项目标准：能讲清接口设计、goroutine/并发控制、缓存策略、错误处理、工程结构和至少一个可验证的二次开发点。
- 里程碑验收问题：为什么选择 gin 或 hertz？GORM 查询如何避免 N+1 或慢 SQL？消息队列消费失败和幂等如何处理？

## 全栈

- 底层基线：前后端接口契约、鉴权、数据库设计、部署、基础 UI、端到端业务闭环。
- 进阶能力：SSR/CSR 取舍、接口缓存、权限模型、多端适配、自动化测试、日志追踪。
- 推荐项目类型：SaaS MVP、个人 CRM、内容社区、预约系统、知识库系统。
- 最低简历项目标准：能完整讲清需求、架构、数据模型、前后端职责、部署方式和迭代计划。
- 里程碑验收问题：为什么这样划分前后端边界？鉴权 token 如何续期？如何保证接口变更不破坏前端？

## 移动端开发

- 底层基线：页面生命周期、网络请求、本地存储、列表性能、权限申请、打包发布。
- 进阶能力：离线缓存、推送、埋点、热更新、多端框架、崩溃监控、包体积优化。
- 推荐项目类型：记账 App、学习打卡、社区客户端、即时通讯 Demo、IoT 控制端。
- 最低简历项目标准：能展示核心页面闭环、接口联调、本地缓存、异常处理和性能优化点。
- 里程碑验收问题：列表卡顿如何定位？离线数据如何同步？权限拒绝后如何降级体验？

## 冷启动最小信息协议

当用户没有提供岗位、JD、仓库链接、水平时，按顺序收集：

1. 目标岗位方向（必须）
2. 当前阶段（学生、实习、校招、初级、转行，可推断）
3. 时间预算（未提供默认 3-4 周）
4. 已有项目或偏好技术栈（可选，没有就跳过）
