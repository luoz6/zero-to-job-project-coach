# 简历标杆与 Few-Shot 案例库

## STAR 法则

每条项目 bullet 优先包含 Situation、Task、Action、Result。没有实测 Result 时，必须写“预期目标”或“完成后待实测”，不得写成已完成结果。

## 低效表达与高阶表达

- 低效表达：负责接入 Redis 和 RocketMQ，提高了系统速度。
- 高阶表达：设计并实现基于 Redis Streams 与 Caffeine 的热点数据本地缓存方案；预期目标为核心查询接口 P95 响应延迟降低 30% 到 70%，完成后待通过压测验证。

## Java 后端项目 Bullet

- 设计订单状态机与支付回调幂等机制，补齐待支付、已支付、取消、超时关闭等状态流转；通过接口测试覆盖重复回调和异常补偿场景，提升订单链路可验证性。
- 基于 Caffeine + Redis 设计多级缓存方案，针对商品详情高频查询设置本地缓存、远端缓存和主动失效策略；预期目标为 P95 延迟降低 30% 到 70%，完成后待实测。

## 前端项目 Bullet

- 重构后台管理系统的权限路由与菜单渲染逻辑，将角色权限、路由守卫和按钮级控制拆分为独立模块，降低新增角色配置成本。
- 为万级数据列表引入虚拟滚动与接口分页缓存，预期目标为首屏渲染耗时降低 30% 到 60%，完成后待 Lighthouse 和性能面板验证。

## AI 应用开发项目 Bullet

- 构建基于 RAG 的企业文档问答 Demo，完成文档切分、Embedding、向量检索、Prompt 组装和流式回答闭环，并设计召回命中率与人工评测表。
- 对比不同 TextSplitter 的 chunk 大小和 overlap 对召回结果的影响，预期目标为 Top-K 相关文档命中率提升 10% 到 25%，完成后待评测集验证。

## 量化指标规则

- 可以使用预期目标范围，例如延迟降低 30% 到 70%、吞吐提升 20% 到 50%、错误率降低 20% 到 40%。
- 没有实测数据时，必须写“预期目标”或“完成后待实测”。
- 不得写成已完成结果，不得伪造压测数据、用户规模、生产事故或线上收益。
- 指标必须能说明指标来源，例如压测脚本、日志、监控面板、Lighthouse、人工评测集或 SQL 统计。

## 简历防守清单

每条 bullet 必须能回答：

- 场景：为什么要做这个改造？
- 技术选型：为什么选这个技术而不是替代方案？
- 指标来源：数据从哪里来，是否实测？
- 踩坑：遇到过什么一致性、性能、部署或调试问题？
- 回滚方案：如果改造失败如何降级或回退？
